# ADR-002 — El contrato `as_of` es la única vía de lectura de datos

## Estado y fecha

Proposed — 2026-08-07

## Contexto y drivers

El fallo que invalidó el trabajo anterior completo fue leakage temporal, y pasó desapercibido
durante meses. Dos instancias concretas (H-11): el CTE `opta_agg` agregaba eventos por
jugador sin ningún filtro temporal — de modo que en la GW1 el modelo ya conocía los totales
de toda la temporada — y las features usaban `now_cost` (precio de cierre) en vez de
`ph.value` (precio de esa jornada).

Ninguno de los dos era detectable leyendo el código por encima. Ambos producían resultados
que *parecían* excelentes.

Requisitos afectados: REQ-F-002, REQ-Q-001.

## Decisión

El almacén expone una única función pública de lectura:

```python
as_of(season: str, gw: int, columns=None) -> DataFrame   # sólo filas con GW < gw
```

No existe otra API pública para leer datos de entrenamiento o de features. Adicionalmente,
el almacén se instrumenta en runtime: si cualquier ruta de código accede a filas fuera de
la ventana declarada, la corrida falla. La instrumentación corre **siempre**, no sólo bajo
pytest.

## Alternativas consideradas

- **Convención más revisión de código.** Rechazada: es literalmente lo que falló.
- **Auditoría posterior con tests dedicados.** Rechazada: detecta tarde y sólo aquello que
  el auditor pensó en buscar. Los dos leakages reales eran de tipos distintos.

## Consecuencias

### Positivas

- El leakage temporal deja de ser expresable. No es un error que se comete y se audita: es
  un error que no compila.
- La violación se manifiesta durante la corrida, con traza, no en una revisión humana.
- Hace el backtest creíble, que es la premisa de toda la iniciativa.

### Negativas y riesgos

- Obliga a propagar `as_of` por toda la cadena, lo que hace las firmas más verbosas.
- Costo de rendimiento por la instrumentación. Aceptable frente al tamaño de datos.
- No previene leakage no temporal (p. ej. usar `total_points` como feature). Eso se cubre
  con una lista explícita de columnas prohibidas como features.

## Condiciones de revisión

Si el costo de la instrumentación supera el presupuesto de REQ-Q-006, degradar a
verificación por muestreo, nunca a desactivación completa.
